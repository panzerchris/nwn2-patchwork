## Actual game checks

Both documented GOG executable hashes were launched normally as `nwn2main.exe`,
with the supplied default configuration. Module inventories identify the local
`dinput8.dll` as patched, never as stock. Startup receipts show the first caller
`0x42670b` on the same thread as the game window in both builds. Initialization
succeeds; v2 reversal applies only on v2, diagnostics/custom dragging remain off.

First ground input after width resizing responds in both sessions. Original's
first post-maximized-drag input attempt encountered an automation screenshot-cache
error; fresh observation/retry responds, so that particular first click is not
claimed. V2's first caption restore attempt after Alt+Enter had the same tool-cache
error; refresh/retry restores correctly. These are recorded uncertainties, not
evidence of a game input failure.

Both games closed through Alt+F4 without a hang. V2 returned process code 0;
original returned 21221. The original's nonzero exit status is unexplained; no
NWN2 Application Error/WER events (1000/1001) were found in the test interval.
This record does not claim zero exit status on both builds.

After process absence, all three user INIs were restored byte-for-byte, independently
verified against both checkpoints. Canonical v2 was restored. A full save audit
found all 12,424 files unchanged, with none added or missing. No game remains running.

## Defender observations and limits

Defender custom scanning of the exact DLL returned 0 / no threats, with engine
`1.1.26100.4` and signatures `1.463.21.0`. Antivirus and real-time protection were
enabled. No new detection/quarantine events (1116/1117) were found from 14:30 UTC
through the two smoke sessions and the DLL remained intact. No exclusions,
quarantine restoration or protection-setting changes were used.

This is a local observation, **not antivirus certification or a guarantee about
future engines or other vendors**. The old 0.1.0 launcher review is still pending;
it remains held and is not included here.

Minimize/focus-loss recovery, original mode changes and optional borderless retain
the historical both-build evidence in [validation](../validation.md); those full
permutations were not repeated for this delivery-only change. Snap, mixed DPI,
long sessions and arbitrary loader/mod combinations remain unvalidated. Native
drag pauses and native small-window HUD scaling limitations remain accepted limits.
